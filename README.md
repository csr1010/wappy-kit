WhatsApp is where 2 billion people already talk to businesses — and the tooling still treats it like a fax machine. Twilio, Gupshup, Landbot: drag-and-drop flow builders, not agents, and none of them can call *your* API as a tool. If you already have a store, a booking system, a CRM, anything with an API — there's no open, code-first way to put a real, memory-aware agent in front of it on WhatsApp.

That's the gap. This is the fill.

```bash
npm create wappy
```

Answer three questions. Get a runnable WhatsApp agent, wired to your model, your memory, your number, your API. No flowchart. No vendor lock-in. No forced cloud.

## Why this exists

Every "WhatsApp agent" you've seen is one of two things: a rigid flow builder wearing an AI costume, or a hosted SaaS that owns your data and your model choice. We wanted neither. So we built the thing we actually wanted to run:

- **Local-first.** Memory lives in a SQLite file on your machine by default. Nothing phones home unless you tell it to.
- **Bring your own everything.** Your WhatsApp number, your model (OpenAI, Anthropic, Gemini, or a fully offline Ollama), your API. We don't own any of it, and we can't rug-pull you on any of it.
- **A router, not a workflow canvas.** The core insight: most messages are cheap. "hi" should never touch your vector store or your production API. Wappy Kit's router decides the *cheapest correct path* per message — so your API only gets called when a message genuinely needs it.
- **Real tools, not toy demos.** Point it at any OpenAPI/Swagger spec and get typed, callable tools automatically. No MCP server required, no third-party SaaS in the loop, no per-call billing.

We tested this by hand, end to end, against a real Shopify store and a real WhatsApp number, chasing down the actual Meta API rejections and actual GraphQL contracts along the way — not just green checkmarks in CI. What ships works.

## What's actually in the box

### Core — the SDK itself

Every `create-wappy` install pulls in exactly these, and nothing else. No connector, no Shopify, no API-specific code rides along by default.

| Package | What it is |
|---|---|
| `@wappy/core` | Contracts, the plugin registry, the install-state ledger. The hub everything else depends on. |
| `@wappy/harness` | The agent runtime — model loop, router, memory, skills, RAG, tool invocation. |
| `@wappy/whatsapp` | The WhatsApp channel — rich message rendering, delivery retries, fallback ladder, real webhook server, typing indicators. |
| `create-wappy` | The CLI. Interview → runnable project. This is the *only* package whose install you pay for — it depends on the three above, nothing more. |

### Connectors — opt-in, added only if you ask for them

Not part of the core install. A generated project only depends on these if you pick them in the interview — their dependencies (and Shopify's, specifically) never land on your machine otherwise.

| Package | What it is |
|---|---|
| `@wappy/tools-openapi` | Point it at any OpenAPI/Swagger spec, get back real callable tools. Includes a hand-built Shopify connector (products, orders, inventory, customers over Shopify's real GraphQL Admin API), since Shopify doesn't publish an OpenAPI spec of its own. |

**One command install, one webhook server, one real agent:**

```bash
npm create wappy
cp .env.sample .env    # fill in your model key + WhatsApp creds
npm install
npm run dev             # boots the server, opens a tunnel, prints the URL for Meta's webhook config
```

Text your number. Get a real reply, generated by your model, grounded in your actual data.

## What you can build *next*

Shopify is the proof, not the ceiling. The same three primitives — a generic OpenAPI→tools engine, a skill system, and a router that decides when to use either — work for anything with an API:

- 🏋️ **A fitness coach** that reads your Fitbit data, nudges you to work out, and suggests a gym nearby — no flow builder, just a skill and a couple of tools.
- 🎫 **A support agent** that sits in front of your own ticketing API and actually resolves things, instead of collecting an email address and vanishing.
- 🍽️ **A booking agent** for a restaurant, a clinic, a studio — anything with a reservations API.
- 🏠 **A leasing agent** that answers "is this still available" from your real listings API, not a stale spreadsheet someone forgot to update.
- 🧠 **A personal assistant** wired to your calendar, your notes, your own internal tools.
- 🏢 **An internal ops bot** — IT helpdesk, HR FAQs, whatever your company already runs on an API, now reachable from the app your team already has open all day.

None of these ship in this repo — and that's deliberate. Wappy Kit is the foundation: it owns the WhatsApp protocol, the agent loop, and the API→tools engine, and nothing else. Your domain logic is yours. Build it as its own app on top, using the same interfaces the Shopify connector uses (`Skill`, `ToolProvider`, `Memory`, `MessageChannel`) — no fork required.

## How it actually works

```
WhatsApp message
      │
      ▼
┌─────────────┐     "hi" → straight to the model. Cheapest path, no tools touched.
│   Router    │
└──────┬──────┘     "what are your hours?" → RAG, grounded in your real data.
       │
       ▼             "where's my order?" → your real API, called for real, checked
┌─────────────┐      against a real tool schema, with a confirm-before-write gate
│ Skill+Tools │       on anything destructive.
│   or RAG    │
└──────┬──────┘
       │
       ▼
   Real reply, sent, persisted, traced.
```

Every step degrades instead of breaking: a rich message that WhatsApp rejects falls back to plain numbered text (with the real content still intact, not silently dropped). A model timeout gets an honest "give me a second" instead of a crash. A closed 24-hour session window queues instead of violating WhatsApp's own policy. Read the full design in [`docs/SPEC.md`](docs/SPEC.md) if you want the receipts.

## Requirements

- **Node.js 20+**
- **A WhatsApp Cloud API app** — free, via [Meta's developer portal](https://developers.facebook.com/apps). You'll need a phone number, an access token, and an app secret. `create-wappy`'s generated README walks you through every field.
- **A model API key** — OpenAI, Anthropic, or Gemini. Or skip the key entirely and run fully offline against local Ollama.
- **A Shopify store** — only if you want the built-in connector. A free development store works fine for testing.

No credit card. No signup for Wappy Kit itself. No forced cloud service in the critical path — the only network calls a generated project makes are to the providers *you* chose.

## Under the hood, if you're curious

- **Router-first architecture.** A cheap, typed decision layer (not a second LLM call dressed up) decides intent, whether RAG or tools are needed, and confidence — before anything expensive happens.
- **Real reliability, not a demo.** Idempotent webhook handling, exponential backoff with jitter, a fallback ladder from rich messages to plain text, a persistent outbound queue that survives a crash mid-send.
- **Context budgeting built in.** History gets windowed and summarized, tool schemas get curated (BM25-selected, not dumped wholesale), so "hi" never pays the token cost of your full 200-tool API surface.
- **Every claim in this README was checked against the real thing.** The Shopify connector's GraphQL contracts, the WhatsApp Cloud API's actual rejection reasons, the typing-indicator payload shape — pulled from real docs and real API responses while building this, not assumed from memory.
