# M12 — Generic cognitive prompting; reference skills removed

**Spec:** §6.1, §6.3, §13 · **Depends on:** M4 (send/render/constraints), M6 (compose-with-budget), M8 (reference skills, being removed here), M9 (create-wappy interview/generator) · **Tag:** `m12-done` · **Packages:** `@wappy/core`, `@wappy/whatsapp`, `@wappy/harness`, `create-wappy`

**Goal:** Every hand-authored, domain-specific instruction the agent relied on (a skill telling it to "prefer a list for products," a skill telling it "never fabricate an order") gets replaced by a small number of fixed, generic instructions that apply to every reply, for every connector, forever — never re-authored per domain. What's left of "Skill" is a documented extension point in `@wappy/core` for an app built on top; Wappy Kit itself ships none.

**Explicitly out of scope, deferred, not touched:** `@wappy/tools-openapi` internals, how Shopify's tools are created/wrapped (still hand-written `Tool` objects over GraphQL), any MCP work. The long-term direction (leverage Shopify's own MCP server instead of hand-mapping their API) is a real, separate future milestone — logged here, not built now.

## How this milestone came together (context for a cold read)

Found by hand-testing a real conversation: `products`' skill said "prefer WhatsApp's list message... name and price" — a retail-specific formatting instruction baked into one skill, which doesn't scale to "thousands of types of responses" from connectors that aren't stores. Investigating the fix surfaced a bigger finding: tracing what `Skill` actually contributes (routing signal, prompt guidance, tool floor, memory schema) against what's already generic in the router/compose pipeline showed that none of it is load-bearing the way it looked:

- Tool *selection* already draws from the full tool pool via BM25 relevance to the message, not skill membership.
- RAG firing depends only on `needsRAG` (a router boolean) — `store-info`'s skill wrapper was never actually gating it.
- All three skills' "honesty" sentences say the identical thing in different words — that's one universal principle, not three domain-specific ones.
- `memorySchema` is documentation only; core never reads it.

So the fix isn't "write a better generic skill." It's recognizing the skill layer wasn't earning its keep for anything Wappy Kit ships itself, and replacing it with instructions that are true regardless of domain.

## Design decisions (confirmed with the user — do not re-litigate)

1. **No per-skill format hints, anywhere.** One generic, fixed instruction decides format for every reply.
2. **The model's format reasoning is captured and traced** (`formatRationale`), not just prompted-and-discarded.
3. **Runs on every reply, no exceptions**, including a plain "hi" — a deliberate, explicit trade against the router's cheapest-path principle.
4. **The generic instructions use zero domain language** — no "store," "product," "order," "shop," "customer," "inventory." They reason from content shape (count of items, one clear action, would media help), never from business type.
5. **Reference skills (`store-info`/`orders`/`products`) are removed entirely**, not kept as optional overrides. `Skill` stays in `@wappy/core` as an extension point; this repo ships none.
6. **Tools/MCP: untouched.** Not this milestone.
