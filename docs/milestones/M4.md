# M4 — WhatsApp smart send + fallback

**Spec:** §6.1, §6.2, §6.3 · **Depends on:** M1, M3 · **Tag:** `m4-done` · **Package:** `@wappy/whatsapp`
**Goal:** Any valid `SmartMessage` is delivered — or degrades honestly. Never a silent failure.

## Read / skip
Read: §6.1–6.3, §10 messaging. Skip: harness/tools.

## Tasks
- [ ] **T4.1** Renderers `SmartMessage → Cloud API payload`: text (+formatting, URL preview), reply buttons, list, CTA-URL, media (image/document/video/audio/voice + caption), location, reaction, quoted reply (`context.message_id`), typing/mark-as-read.
- [ ] **T4.2** Constraint layer (single source of truth for limits): buttons ≤3, title ≤20, list ≤10 rows, row title ≤24, desc ≤72, body length; auto-truncate with ellipsis or degrade; unicode/emoji-safe truncation (no split surrogate pairs).
- [ ] **T4.3** Fallback ladder: rich → numbered plain text ("Reply 1 for …") and inbound handler maps a numeric/text reply back to the option. Triggered by pre-send validation failure, Meta rejection code, or non-delivery.
- [ ] **T4.4** Window guard: closed window → block free-form; choose approved template (variable + button mapping) or queue; result is `queued`/`templated`, never dropped.
- [ ] **T4.5** Templates: registry of approved templates, variable mapping, validation.
- [ ] **T4.6** Retry engine: injectable `Clock`; exponential backoff + jitter on 429/5xx, honor `Retry-After`; delivery state machine driven by status webhooks (sent→delivered→read | failed→retry→fallback); max attempts.
- [ ] **T4.7** Meta error-code map (table → action: retry | fallback | template | drop-with-log | alert); unknown codes → safe default. Codes marked "verify against Meta docs" in a comment until confirmed.
- [ ] **T4.8** Persistent outbound queue (survives restart) with idempotency key so a retry after crash never double-sends.
- [ ] **T4.9** Outbound media validation (size/mime) with clear errors.
- [ ] **T4.10** Implement `MessageChannel.send`; conformance suite green; golden payloads in `fixtures/whatsapp/outbound/*.json`.

## Tests introduced (`*.m4.test.ts`)
- Table-driven constraint tests (boundary ±1 for every limit; emoji/RTL/CJK titles).
- Golden payload snapshot per message type.
- Mock Cloud scripts: reject-rich→text fallback; 429→backoff→success (fake clock); 5xx×max→`failed`+fallback; delivery `failed` webhook → retry → fallback; duplicate send after crash → single delivery.
- Window closed at 24h01m → template path; no template configured → queued with reason.
- Numbered-fallback reply mapping round-trips.
