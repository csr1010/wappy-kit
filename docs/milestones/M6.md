# M6 — Context management (large contexts)

**Spec:** §10 (prompt/token overflow, too many tools), §8 (spec-bloat), §7 · **Depends on:** M5 · **Tag:** `m6-done` · **Package:** `@wappy/harness`
**Goal:** No prompt ever exceeds the model window; large inputs/outputs are bounded and degrade honestly.

## Tasks
- [x] **T6.1** `ContextBudget`: per-model window + reserved output tokens (config; sane defaults; unknown model → conservative default). Pluggable `TokenEstimator`; fallback = conservative `chars/3.5`. Optional real-tokenizer estimator behind an optional dep.
- [x] **T6.2** Deterministic **prompt assembler** (replaces M5's naive one): fixed ordering `system → skill fragments → tool schemas → summary → recalled snippets → recent turns → user message`; stable prefix (prompt-cache friendly); each section has a token cap; drops lowest-priority sections first, **never** the user message or system prompt.
- [x] **T6.3** History windowing + rolling **summarization**: when history exceeds its share, summarize the oldest chunk with a cheap model call; persist summary in Memory; on summarizer failure fall back to plain truncation.
- [x] **T6.4** `recall(query)` snippet cap + relevance floor; never inject more than budget.
- [x] **T6.5** `ToolSelector` (runtime tool retrieval): default **lexical/BM25** over name+description (no embeddings needed), optional embedding selector; picks top-K tools per message; K bounded by tool-schema token budget. Skill-declared tools always eligible.
- [x] **T6.6** Tool-result bounding: cap size → truncate + structured summary (`{truncated, totalBytes, shown, hint}`); arrays paged/limited; never pass raw megabytes to the model.
- [x] **T6.7** Oversized inbound (huge text/caption): truncate with an honest notice; extremely large → polite refusal, still one reply.
- [x] **T6.8** Provider "context too long" error (normalized across providers): shrink budget 25%, retry **once**, else honest degrade message.
- [x] **T6.9** Trace token usage per section per message (observability; also used by tests).

## Tests introduced (`*.m6.test.ts`)
- **Property test:** for random histories/tool sets/skill sizes, assembled prompt ≤ budget and always contains system + user message.
- 10,000-turn history fixture → bounded latency and size; summary persisted; second message reuses summary (no re-summarize).
- Summarizer throws → truncation fallback, reply still sent.
- 800-tool set → selector returns ≤K, includes the obviously relevant tool for 20 labeled queries (recall@K threshold).
- 5 MB tool result → truncated with summary; model never sees > cap.
- Context-length error → exactly one retry with smaller budget, then honest message.
- Snapshot of assembled prompt for fixed input (determinism / stable prefix).
